# Админка АнТех Восток — план реализации

Решение: JSON, собственный сервер, заранее созданные логины/пароли и права. Без регистрации, Supabase и входа через почту.

- [x] Хранилище: один приватный JSON, блокировка между процессами, атомарная замена, версии/конфликты, резервные копии. Фото/PDF отдельно, вне каталога сборки.
- [x] Пользователи: создание/сброс пароля через локальную команду; owner/editor, хеш scrypt, серверные сессии, выход/отзыв, защита входа и изменений.
- [x] Каталог API: импорт существующего каталога, черновик отдельно от публикации, копирование, скрытие/возврат, история и восстановление в черновик.
- [x] Файлы: до 3 фото, оптимизация, главное фото/порядок, PDF, ограничение размера, приватность неопубликованных файлов.
- [x] UI: Вход в хедере; список/поиск/фильтры; простая форма; характеристики строками; параметры заявки (список/число/текст); предпросмотр; понятные статусы, защита несохранённых изменений.
- [x] Публичный каталог получает опубликованные данные API без пересборки; новые параметры/фото работают в заявке. При отказе API — явная ошибка и повтор, без возврата скрытых товаров из старой сборки.
- [x] Эксплуатация: постоянный каталог данных, запуск вместе с сайтом, команды пользователей/backup/restore, подготовка Nginx/Compose; первая локальная учётная запись.
- [x] Проверки: реальные HTTP и диск (включая параллельные записи), права/CSRF/пароли/файлы/конфликты; браузерный цикл редактора, мобильный вид/клавиатура/доступность; SMTP и публичный сайт.

Публикация на внешнем сервере и реальные почтовые настройки остаются отдельным этапом. Вход в админку от SMTP не зависит. Генерируемые пароли выдаются локальным файлом с правами 0600, не попадают в логи, Git или публичный JSON.

Реализовано и проверено локально 2026-10-09. Фактические результаты и ограничения — QA_REPORT.md. Production-контейнеры, внешний хостинг и доставка в реальный ящик не запускались.
