# АнТех Восток

Корпоративный сайт производителя: Next.js, TypeScript, статический экспорт, каталог продукции и услуг, составление общей заявки и закрытый редактор.

## Локальный запуск

```sh
npm ci
npm run dev -- --hostname 127.0.0.1
```

Без внешних настроек каталог работает из `content/catalog.json`. Заявка сохраняется в sessionStorage текущей вкладки. Кнопка «Подготовить запрос» создаёт текст: его можно скопировать или открыть в почтовом приложении. Сам сайт при этом ничего не отправляет. Согласие не восстанавливается автоматически.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run test:db
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:connected
```

Браузерные проверки запускают сервер production-сборки на 127.0.0.1:3100. Скриншоты сохраняются в `qa/screenshots`, отчёт — `playwright-report`. База проверяется изолированно в PostgreSQL/PGlite: миграции, повторное заполнение, публичное чтение, запрет чужой записи и повышения прав, работа редактора и ограничения данных. Это не проверка живого Supabase.

## Каталог и Supabase

1. Создать проект Supabase. Выполнить SQL-файлы `supabase/migrations/001_catalog.sql`, `002_catalog_details.sql`, `003_catalog_content.sql` по порядку.
2. Отключить самостоятельную регистрацию. Пригласить только подтверждённых редакторов в Supabase Auth.
3. Добавить их UUID в `public.site_admins`. Публичным пользователям запись в эту таблицу запрещена.
4. Разрешить production URL `/admin/` в Auth Redirect URLs.
5. Указать `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` при сборке. Service-role ключ сайту не нужен и не должен попадать в клиент.

Редактор управляет названием, описанием, характеристиками, исполнениями, выбором длины, применением и ссылками на документы. Самостоятельная загрузка файлов и удаление позиций не предусмотрены. Документы сначала кладутся в `public/files/`, выпускаются вместе с сайтом и только затем добавляются в редакторе как `/files/name.pdf`.

Миграция 003 заменяет только точные старые заглушки. Повторный запуск не перезаписывает ручные правки. При дальнейшем обновлении содержимого обновляйте и JSON, и новую миграцию; тест проверяет совпадение начальных данных.

## Отправка формы

Адрес получателя: info@antekh.ru. Для автоматической отправки требуется рабочий Formspree endpoint в `NEXT_PUBLIC_FORM_ENDPOINT`. Один адрес почты не включает отправку. До подключения нужно завершить сведения об обработке данных. После настройки проверить реальную доставку, ошибки и защиту от спама; без настройки показывается режим подготовки письма.

Все `NEXT_PUBLIC_*` встраиваются в сборку: после изменения пересобрать сайт. Переменные перечислены в `.env.example`; реальные значения хранить в игнорируемом `.env.local`.

## Материалы и выпуск

- `WORK_PLAN.md` — выполненные шаги и границы текущего выпуска.
- `CUSTOMER_CHECKLIST.md` — только нерешённые уточнения.
- `MATERIALS.md` — происхождение контента и исключения.
- `QA_REPORT.md` — результаты фактических проверок.

`npm run build` создаёт `out/`. Развёртывание подготовлено в `deploy/`: Nginx, HTTPS и ссылка current на каталог релиза. Домен и production-доступы пока не подтверждены; публикация не выполнялась. До выпуска заполнить `NEXT_PUBLIC_SITE_URL`, подключить сервисы, завершить правовой текст и согласовать оставшиеся материалы.
