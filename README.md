# АнТех Восток

Корпоративный сайт производителя: Next.js, TypeScript, статический экспорт, каталог продукции и услуг, составление общей заявки. Каталог хранится в файле, без внешней базы и аккаунтов редакторов.

## Локальный запуск

```sh
npm ci
npm run dev -- --hostname 127.0.0.1
```

Без внешних настроек каталог работает из `content/catalog.json`. Заявка сохраняется в sessionStorage текущей вкладки. Кнопка «Подготовить запрос» создаёт текст: его можно скопировать или открыть в почтовом приложении. Сам сайт при этом ничего не отправляет. Согласие не восстанавливается автоматически.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:connected
npm run test:mail
npm run test:mail:browser
```

Браузерные проверки запускают сервер production-сборки на 127.0.0.1:3100. Скриншоты сохраняются в `qa/screenshots`, отчёт — `playwright-report`. Каталог валидируется при сборке: проверяются уникальные ID, типы позиций, названия, описания, характеристики и ссылки на документы.

## Как обновлять каталог

Единственный источник — `content/catalog.json`. Планируемый объём — до 100 товаров и услуг. Меняем нужные записи, запускаем `npm test` и `npm run build`, проверяем результат локально и выпускаем новую статическую сборку. Существующие ID сохраняем: на них опирается состав заявки в браузере. Для новых позиций задаём новые постоянные ID. Порядок карточек соответствует порядку записей в файле.

Поля: `item_type` (`product`/`service`), `title`, `description`, `details` (характеристики, исполнения, выбор длины, применение и документы). Формат можно взять из соседней позиции. PDF размещаются в `public/files/` и указываются как `/files/name.pdf`.

Публичного редактора и регистрации нет. Изменения вносит разработчик через файлы проекта; прежняя реализация с Supabase сохранена только в истории Git.

## Отправка формы

Подготовлен собственный SMTP API: `server/`. Форма отправляет JSON на `/api/request`, Nginx передаёт его отдельному Node-процессу. Отправитель и получатель задаются только на сервере; можно использовать один ящик для обоих. Email посетителя становится Reply-To. Formspree остаётся совместимым при внешнем endpoint.

Без SMTP и включённого endpoint сайт по-прежнему только готовит письмо. Настройка и запуск описаны в `INTEGRATIONS.md`. SMTP-приёмник и браузерный путь проверяются без реальных адресов командами `npm run test:mail` и `npm run test:mail:browser`. Вторая команда временно пересобирает out/ и затем восстанавливает обычную конфигурацию; не запускать на публичном статическом каталоге.

Все `NEXT_PUBLIC_*` встраиваются в сборку: после изменения пересобрать сайт. Переменные перечислены в `.env.example`; реальные значения хранить в игнорируемом `.env.local`.

## Материалы и выпуск

- `WORK_PLAN.md` — выполненные шаги и границы текущего выпуска.
- `CUSTOMER_CHECKLIST.md` — только нерешённые уточнения.
- `MATERIALS.md` — происхождение контента и исключения.
- `QA_REPORT.md` — результаты фактических проверок.

`npm run build` создаёт `out/`. Развёртывание подготовлено в `deploy/`: Nginx, HTTPS и ссылка current на каталог релиза. Домен и production-доступы пока не подтверждены; публикация не выполнялась. До выпуска заполнить `NEXT_PUBLIC_SITE_URL`, подключить сервисы, завершить правовой текст и согласовать оставшиеся материалы.
