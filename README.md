# АнТех Восток — сайт и каталог продукции

Корпоративный сайт производителя анкеров и комплектующих. В проект входят публичные страницы, каталог продукции и услуг, форма общей заявки, сервер каталога в JSON и закрытая админка.

**Состояние на 16 октября 2026:** сайт и API запускаются локально; SMTP отправляет письма через Mail. Владелец ящика подтвердил получение тестового письма во «Входящих». Постоянного внешнего размещения ещё нет. Сайт по последней просьбе показывается без добавленных фотографий и схем.

## Возможности

- Главная, каталог, производство, документы, контакты и предварительная страница обработки персональных данных.
- Каталог хранится в JSON на сервере. Черновики отделены от опубликованных позиций; есть история, резервные копии, загрузка изображений и PDF.
- Админка `/admin/`: вход по заранее созданным логину и паролю, роли owner/editor, без самостоятельной регистрации.
- Посетитель может выбрать несколько товаров и услуг, заполнить параметры, количество и контакты, затем отправить единую заявку.
- SMTP работает через отдельный Node API. Заявки адресуются на настроенный ящик; данные заявки не сохраняются в JSON каталога.
- Supabase не используется.

## Локальный запуск

Требуются Node.js и npm. Установить зависимости один раз:

```sh
npm ci
```

Если локальные `.env.server` и `.env.local` уже настроены, **не перезаписывайте их**. Для первой установки скопируйте примеры:

```sh
cp .env.server.example .env.server
cp .env.example .env.local
```

Запустите API в первом терминале:

```sh
npm run start:api
```

Во втором терминале запустите сайт:

```sh
npm run dev -- --hostname 127.0.0.1
```

Откройте <http://localhost:3000/>. Каталог находится по адресу <http://localhost:3000/catalog/>, админка — <http://localhost:3000/admin/>. API слушает только `127.0.0.1:3101`. Запуск сайта без API оставит страницы доступными, но каталог, админка и отправка заявок не будут работать полноценно.

Данные каталога, учётные записи и загруженные файлы располагаются в игнорируемой папке `.local/`. Первый каталог импортируется из `content/catalog.json`. Настройка редакторов, резервное копирование и восстановление описаны в [ADMIN_GUIDE.md](ADMIN_GUIDE.md).

## Почта и заявки

Локальная конфигурация SMTP хранится только в `.env.server`. Этот файл, `.env.local`, `.local/` и исходный `SMTP_passw.txt` исключены из Git. Пароль приложения нельзя добавлять в `NEXT_PUBLIC_*`, код, коммиты или сообщения.

- `npm run mail:check` проверяет SMTP-соединение и вход, не отправляя письмо.
- `npm run mail:test` отправляет одно техническое письмо на `MAIL_TO`.
- На этом компьютере SMTP-настройки проверены; техническое письмо и тестовая заявка дошли до настроенного ящика. Отправитель и получатель — один ящик. Публичный адрес компании в содержимом сайта остаётся `info@antekh.ru`.
- Тесты не заменяют проверку ящика после переноса на сервер: SMTP-доступ, секреты и исходящий сетевой доступ надо настроить и проверить в окружении размещения.

Форма проверяет согласие и контакт посетителя, ограничивает частоту запросов и не принимает адрес получателя из браузера. При подтверждённой отправке черновик формы очищается. Техническая карта данных — [DATA_PROCESSING.md](DATA_PROCESSING.md); текст политики сейчас предварительный и требует завершения до открытия сайта.

## Проверки

Основные команды:

```sh
npm run typecheck
npm run lint
npm test
npm run test:server
npm run build
NEXT_PUBLIC_FORM_ENDPOINT= npm run build
npm run test:e2e
npm run build
```

Для E2E перед тестами нужна сборка без активной формы: команда `NEXT_PUBLIC_FORM_ENDPOINT= npm run build` отключает реальную отправку только в тестовом `out/`. После E2E повторный обычный `npm run build` восстанавливает сборку из `.env.local`. Так браузерные проверки не отправят письмо в настоящий ящик. Не запускайте `test:e2e` на случайной сборке `out/`: набор включает сценарий подготовки письма, который не соответствует включённой отправке.

**Проверки 16 октября:** ESLint, TypeScript, 7 unit-тестов, 10 серверных тестов и 11 браузерных E2E-сценариев прошли. Затем обычная production-сборка с SMTP endpoint восстановлена. SMTP-вход, отправка через браузерную форму и доставка тестового письма подтверждены владельцем ящика 14 октября. Полная история и ограничения собраны в [QA_REPORT.md](QA_REPORT.md).
