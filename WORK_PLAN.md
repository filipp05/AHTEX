# Актуальный план — 9 октября 2026

## Принятое решение

Без Supabase и внешней базы. До 100 товаров/услуг хранятся в content/catalog.json. Обновления вносит разработчик и выпускает вместе с сайтом. Аккаунты редакторов и публичная админка не нужны. Это решение заменяет предыдущий этап подготовки Supabase; старый код доступен в Git.

## Сделано

- [x] Наполнение сайта по материалам заказчика, бренд, каталог с характеристиками и исполнениями.
- [x] Минималистичное оформление, адаптивность, крупные контакты, удаление лишней полосы аудитории.
- [x] Единая заявка с исполнениями, длиной, количеством и сохранением черновика.
- [x] Собственный SMTP API и локальная проверка браузер → HTTP → SMTP.
- [x] Каталог из файла, валидация при сборке, удаление Supabase/админки/миграций/зависимостей.
- [x] Инструкции обновления каталога и техническая карта обработки данных.

## До публикации

- [ ] Получить фото, документы, разрешения и ответы на фактические вопросы заказчика.
- [ ] Получить SMTP-настройки, подключить отправку и проверить реальную доставку.
- [ ] Подтвердить сроки хранения, ответственных и порядок удаления обращений; завершить политику.
- [ ] Определить домен/сервер, проверить контейнерный запуск, DNS и HTTPS, выпустить сайт и проверить его после публикации.

Ответственность: заказчик подтверждает факты, материалы и обработку обращений; мы готовим код, оформление, технические настройки и текст политики. Создание Supabase-проекта и адреса редакторов из плана исключены.
