# Почта: что готово и как подключить ящик

Для локальной проверки SMTP уже подключён. Хостинг и домен для локального просмотра не нужны. Форма поддерживает автоматическую отправку через собственный API, а без настроенного endpoint готовит текст письма; в этом режиме выбранные файлы пользователь прикладывает в почтовом приложении вручную.

## Что потребуется от владельца

1. Название почтового сервиса и адрес ящика.
2. Адрес, куда получать заявки (может совпадать с отправителем; может быть Proton).
3. Пароль приложения / SMTP-токен, если сервис использует его. Сохранить локально в `.env.server`, не присылать в чат. Конкретный способ выдачи доступа проверяем после выбора сервиса.

Поддерживается SMTP с логином и паролем/токеном на порту465 или587, с обязательным TLS. Если выбранный сервис допускает только OAuth, его подключение потребует отдельной адаптации.

## Подключение — выполняет разработчик

Не перезаписывать существующий `.env.server`: в нём также настройки каталога и резервирования. Заполнить только:

| Переменная | Значение |
|---|---|
| SMTP_HOST | SMTP-сервер из инструкции провайдера, без https:// |
| SMTP_PORT | 465 или587 |
| SMTP_USER | Логин SMTP, обычно полный email |
| SMTP_PASS | Пароль приложения или SMTP-токен |
| MAIL_FROM | Разрешённый сервисом адрес отправителя |
| MAIL_TO | Единственный адрес получателя заявок |

1. `npm run mail:check` — проверяет полноту настроек, защищённое соединение и авторизацию. Письмо не отправляет. Пароли, адреса и сырые ответы провайдера не выводит. При ошибке код завершения1 и краткое объяснение.
2. `npm run mail:test` — явно отправляет одно техническое письмо на MAIL_TO. Проверить вручную «Входящие» и «Спам». Успешный SMTP-ответ не означает гарантированного попадания во входящие.
3. Перезапустить API: `npm run start:api`. Если процесс уже запущен, сначала штатно остановить именно его.
4. В `.env.local` установить `NEXT_PUBLIC_FORM_ENDPOINT=/api/request`. Для localhost перезапустить Next dev; для статической сборки выполнить `npm run build`. Серверный `.env.server` не копировать в `.env.local` или `out/`.
5. После согласования порядка обработки данных отправить из формы одну тестовую заявку с вымышленными данными. Проверить состав, параметры, количество и возможность ответа на email посетителя. Если email не указан, в письме остаётся телефон.

Отправитель и получатель задаются только на сервере. Посетитель не может подменить адрес назначения; его email используется в Reply-To. Форму очищаем после подтверждения API. При отказе данные остаются. Заявки не записываются в JSON каталога. Автоматических повторов и очереди нет; повтор после неопределённого сетевого сбоя иногда может дать дубль. Одинаковые успешно принятые заявки подавляются в течение10минут работы процесса.

## Откат

Очистить NEXT_PUBLIC_FORM_ENDPOINT и перезапустить dev / пересобрать статический сайт. Форма вернётся к подготовке письма. Если требуется отозвать почтовый доступ, отозвать токен у провайдера, очистить SMTP_PASS и перезапустить API. Админка и каталог работают без почты.

## Проверки сейчас

`npm run test:server` проверяет реальный локальный SMTP, ограничения API и диагностику настроек. `npm run test:mail:browser` проходит браузер→API→локальныйSMTP, включая ошибку, повтор, параметры заявки и очистку формы. Он временно пересобирает `out/` и восстанавливает обычную конфигурацию; не запускать на рабочем каталоге опубликованного сайта.

Внешняя почта в этих проверках не используется. Реальные секреты не требуются. Финальная доставка в выбранный ящик остаётся этапом подключения.
